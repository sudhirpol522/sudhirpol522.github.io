f:T25ac3,<p>If you are optimizing inference engines or writing custom CUDA kernels for modern LLMs, you inevitably hit the memory wall. Serving a 70B parameter model in FP16 requires over 140GB of VRAM, forcing you into multi-GPU tensor parallelism just to load the weights.</p>
<p>Post-Training Quantization (PTQ) algorithms like GPTQ solve this by compressing weights down to 4-bits or 3-bits. But if you naively round the weights of a massive LLM, you destroy the model's perplexity.</p>
<p>GPTQ survives aggressive quantization by recognizing a fundamental truth: weights do not act in isolation. If you force one weight down, you can calculate exactly how much to push the neighboring weights up to absorb the structural damage.</p>
<p>In this post, we will derive the exact mathematics behind GPTQ from scratch using Lagrange multipliers, shadow-run a 2D example, translate the derivation into vectorized PyTorch code, and finally pack the resulting 4-bit integers into dense 32-bit checkpoint tensors.</p>
<hr>

<h2>Part 4: The Secret of Row Independence</h2>
<p>If we have a massive weight matrix of shape <code>[out_features, in_features]</code>, do we need a massive, uncomputable Hessian?</p>
<p>No. In a linear layer, output neurons do not share weights. When you change a weight in Row 1, you only damage the output of Neuron 1. Neuron 2 is completely unaffected.</p>
<p>Therefore, we only need the Hessian of the input features (shape <code>[in_features, in_features]</code>). We can apply this exact same small inverse Hessian to optimize every single row of the weight matrix independently.</p>
<p>Even better, we don't have to write a <code>for</code> loop across the rows. We can use vectorization to update every single output neuron simultaneously.</p>
<hr>
<h2>Part 5: The Vectorized PyTorch Implementation</h2>
<p>Here is the exact mathematical core of GPTQ translated into a high-throughput PyTorch execution.</p>
<p>Notice how the algorithm marches sequentially through the columns (<span class="katex"><span class="katex-mathml"><math xmlns="http://www.w3.org/1998/Math/MathML"><semantics><mrow><mi>q</mi><mo>=</mo><mn>0</mn><mo separator="true">,</mo><mn>1</mn><mo separator="true">,</mo><mn>2</mn><mo>…</mo></mrow><annotation encoding="application/x-tex">q = 0, 1, 2 \dots</annotation></semantics></math></span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.625em;vertical-align:-0.1944em;"></span><span class="mord mathnormal" style="margin-right:0.0359em;">q</span><span class="mspace" style="margin-right:0.2778em;"></span><span class="mrel">=</span><span class="mspace" style="margin-right:0.2778em;"></span></span><span class="base"><span class="strut" style="height:0.8389em;vertical-align:-0.1944em;"></span><span class="mord">0</span><span class="mpunct">,</span><span class="mspace" style="margin-right:0.1667em;"></span><span class="mord">1</span><span class="mpunct">,</span><span class="mspace" style="margin-right:0.1667em;"></span><span class="mord">2</span><span class="mspace" style="margin-right:0.1667em;"></span><span class="minner">…</span></span></span></span>). Once a column is quantized, it is locked. The compensation update is only applied to the remaining columns to its right (<code>q+1:</code>). If we applied the update to the whole matrix, we would add floating-point noise back onto our already-quantized integers, ruining our previous work.</p>
<pre><code class="language-python">import torch

def quantize_to_nearest(w):
    """
    Placeholder for symmetric/affine quantization.
    """
    return torch.round(w)

def gptq_core(W, H):
    """
    W: Weight matrix of shape [out_features, in_features]
    H: Hessian matrix of shape [in_features, in_features]
    """
    out_features, in_features = W.shape
    Q = torch.zeros_like(W)

    # 1. Hessian Preparation (Dampening for numerical stability)
    dead = torch.diag(H) == 0
    H[dead, dead] = 1
    dampening = 0.01 * torch.mean(torch.diag(H))
    H = H + torch.eye(in_features) * dampening

    # In production, use Cholesky decomposition instead of raw inverse
    # to prevent floating-point catastrophic cancellation on massive matrices.
    # H_inv = torch.linalg.cholesky(torch.linalg.inv(H), upper=True)
    H_inv = torch.linalg.inv(H)

    # 2. The Core Quantization Loop (Marching left to right)
    for q in range(in_features):

        # Grab the q-th column (active weight for all output neurons)
        w_q = W[:, q]

        # Quantize and lock into our final output matrix
        quantized_w_q = quantize_to_nearest(w_q)
        Q[:, q] = quantized_w_q

        # Step 1: Calculate forced change (shape: [out_features])
        delta_q = quantized_w_q - w_q

        # Step 3: Calculate scale factor lambda (shape: [out_features])
        scale_factor = delta_q / H_inv[q, q]

        # Step 4: The Vectorized Compensation
        # We grab the remaining slice of the inverse Hessian.
        # Note: We slice the row (H_inv[q, q+1:]) instead of the column
        # because PyTorch memory is C-contiguous (row-major). Since the
        # Hessian is perfectly symmetric, row == col, but row is vastly
        # faster for the GPU memory bus.
        h_inv_slice = H_inv[q, q+1:]

        # torch.outer computes the update for ALL output neurons instantly
        update = torch.outer(scale_factor, h_inv_slice)

        # Apply the compensation ONLY to the remaining unquantized weights
        W[:, q+1:] = W[:, q+1:] + update

    return Q

</code></pre>
<h3>Engineering Polish: Why Cholesky?</h3>
<p>If you run the standard <code>torch.linalg.inv</code> on a 70B model, the loop will fail—both numerically and mathematically. First, the inverse of million-element matrices introduces tiny floating-point rounding errors that compound exponentially by the final columns. Second, as columns <span class="katex"><span class="katex-mathml"><math xmlns="http://www.w3.org/1998/Math/MathML"><semantics><mrow><mn>0</mn><mo>…</mo><mi>q</mi><mo>−</mo><mn>1</mn></mrow><annotation encoding="application/x-tex">0 \dots q-1</annotation></semantics></math></span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.8389em;vertical-align:-0.1944em;"></span><span class="mord">0</span><span class="mspace" style="margin-right:0.1667em;"></span><span class="minner">…</span><span class="mspace" style="margin-right:0.1667em;"></span><span class="mord mathnormal" style="margin-right:0.0359em;">q</span><span class="mspace" style="margin-right:0.2222em;"></span><span class="mbin">−</span><span class="mspace" style="margin-right:0.2222em;"></span></span><span class="base"><span class="strut" style="height:0.6444em;"></span><span class="mord">1</span></span></span></span> are locked, they can no longer absorb future error. A static <span class="katex"><span class="katex-mathml"><math xmlns="http://www.w3.org/1998/Math/MathML"><semantics><mrow><msup><mi>H</mi><mrow><mo>−</mo><mn>1</mn></mrow></msup></mrow><annotation encoding="application/x-tex">H^{-1}</annotation></semantics></math></span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.8141em;"></span><span class="mord"><span class="mord mathnormal" style="margin-right:0.0813em;">H</span><span class="msupsub"><span class="vlist-t"><span class="vlist-r"><span class="vlist" style="height:0.8141em;"><span style="top:-3.063em;margin-right:0.05em;"><span class="pstrut" style="height:2.7em;"></span><span class="sizing reset-size6 size3 mtight"><span class="mord mtight"><span class="mord mtight">−</span><span class="mord mtight">1</span></span></span></span></span></span></span></span></span></span></span></span> tries to route compensation back through already-frozen weights.</p>
<p>Because the Hessian matrix is perfectly symmetrical and positive-definite, production quantization engines swap the raw inverse for an upper-triangular Cholesky decomposition of the inverse (<code>torch.linalg.cholesky(torch.linalg.inv(H), upper=True)</code>). Reading the <span class="katex"><span class="katex-mathml"><math xmlns="http://www.w3.org/1998/Math/MathML"><semantics><mrow><mi>q</mi></mrow><annotation encoding="application/x-tex">q</annotation></semantics></math></span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.625em;vertical-align:-0.1944em;"></span><span class="mord mathnormal" style="margin-right:0.0359em;">q</span></span></span></span>-th row of this upper Cholesky factor automatically provides the exact conditional inverse of <em>only</em> the remaining unquantized columns while stabilizing floating-point arithmetic, allowing the exact same loop to compress a massive LLM on a single GPU in hours.</p>

<h2>Part 6: From Simulated Floats to 4-Bit Integer Codes (Scales &#x26; Zero-Points)</h2>
<p>Look closely at <code>quantize_to_nearest(w)</code> in Part 5. Using <code>torch.round(w)</code> works as a conceptual placeholder, but real LLM weights live in tiny floating-point distributions (like <span class="katex"><span class="katex-mathml"><math xmlns="http://www.w3.org/1998/Math/MathML"><semantics><mrow><mo>−</mo><mn>0.8</mn></mrow><annotation encoding="application/x-tex">-0.8</annotation></semantics></math></span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.7278em;vertical-align:-0.0833em;"></span><span class="mord">−</span><span class="mord">0.8</span></span></span></span> to <span class="katex"><span class="katex-mathml"><math xmlns="http://www.w3.org/1998/Math/MathML"><semantics><mrow><mo>+</mo><mn>0.7</mn></mrow><annotation encoding="application/x-tex">+0.7</annotation></semantics></math></span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.7278em;vertical-align:-0.0833em;"></span><span class="mord">+</span><span class="mord">0.7</span></span></span></span>). <h2>Part 7: The "Empty Box" Problem — Bit-Packing <code>int4</code> into <code>int32</code></h2>
<p>Even after computing integer codes in the range <code>0..15</code>, we face a hardware problem: <strong>GPU memory is byte-addressable, and PyTorch has no native <code>int4</code> tensor storage.</strong></p>
<p>If you store 16 quantized 4-bit codes inside a <code>torch.int32</code> tensor, PyTorch allocates 32 bits of memory for every single number. Look at what happens when the weight code <code>11</code> (<code>1011</code> in binary) sits inside a 32-bit <code>int32</code> container:</p>
<pre><code class="language-text">[0000 0000 0000 0000 0000 0000 0000 | 1011]
 ^------------ 28 wasted zeros -----^   ^-- 4-bit weight (11)

</code></pre>
<p>Out of 32 bits, <strong>28 bits are wasted zeros</strong>. Storing 16 weights in <code>torch.int32</code> consumes <span class="katex"><span class="katex-mathml"><math xmlns="http://www.w3.org/1998/Math/MathML"><semantics><mrow><mn>16</mn><mo>×</mo><mn>32</mn><mo>=</mo><mn>512</mn><mtext> bits</mtext></mrow><annotation encoding="application/x-tex">16 \times 32 = 512\text{ bits}</annotation></semantics></math></span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.7278em;vertical-align:-0.0833em;"></span><span class="mord">16</span><span class="mspace" style="margin-right:0.2222em;"></span><span class="mbin">×</span><span class="mspace" style="margin-right:0.2222em;"></span></span><span class="base"><span class="strut" style="height:0.6444em;"></span><span class="mord">32</span><span class="mspace" style="margin-right:0.2778em;"></span><span class="mrel">=</span><span class="mspace" style="margin-right:0.2778em;"></span></span><span class="base"><span class="strut" style="height:0.6944em;"></span><span class="mord">512</span><span class="mord text"><span class="mord"> bits</span></span></span></span></span> (64 bytes)—which is actually <em>twice as large</em> as our original FP16 weights!</p>
<h3>How Bit-Packing Compresses 16 Weights into 2 <code>int32</code> Words</h3>
<p>Since one <code>int32</code> container has 32 bits of space and each weight only needs 4 bits, we can pack <strong><span class="katex"><span class="katex-mathml"><math xmlns="http://www.w3.org/1998/Math/MathML"><semantics><mrow><mn>32</mn><mo>÷</mo><mn>4</mn><mo>=</mo><mn>8</mn></mrow><annotation encoding="application/x-tex">32 \div 4 = 8</annotation></semantics></math></span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.7278em;vertical-align:-0.0833em;"></span><span class="mord">32</span><span class="mspace" style="margin-right:0.2222em;"></span><span class="mbin">÷</span><span class="mspace" style="margin-right:0.2222em;"></span></span><span class="base"><span class="strut" style="height:0.6444em;"></span><span class="mord">4</span><span class="mspace" style="margin-right:0.2778em;"></span><span class="mrel">=</span><span class="mspace" style="margin-right:0.2778em;"></span></span><span class="base"><span class="strut" style="height:0.6444em;"></span><span class="mord">8</span></span></span></span> weights</strong> into a single <code>int32</code> word. Think of a 32-bit integer as an apartment building with <strong>8 rooms</strong>, each 4 bits wide:</p>
<pre><code class="language-text">Bit position:  31..28   27..24   23..20   19..16   15..12   11..8    7..4     3..0
              [Room 7] [Room 6] [Room 5] [Room 4] [Room 3] [Room 2] [Room 1] [Room 0]

</code></pre>
<p>Let's walk through a concrete example. Suppose we have <strong>16 quantized 4-bit weights</strong> in <code>int32</code> that we want to compress into <strong>2 packed <code>int32</code> words</strong>:</p>
<pre><code class="language-python">codes = [3, 10, 15, 0, 7, 12, 1, 9,   4, 14, 2, 8, 11, 5, 6, 13]
#        |------- Word 0 -------|     |------- Word 1 -------|

</code></pre>
<h4>Step 1: Split into Groups of 8</h4>
<p>We reshape the 16 codes into 2 groups of 8:</p>
<ul>
<li><strong>Group 0:</strong> <code>[3, 10, 15, 0, 7, 12, 1, 9]</code></li>
<li><strong>Group 1:</strong> <code>[4, 14, 2, 8, 11, 5, 6, 13]</code></li>
</ul>

<pre><code class="language-text">                Room 7  Room 6  Room 5  Room 4  Room 3  Room 2  Room 1  Room 0

                         (9)     (1)    (12)     (7)     (0)    (15)    (10)     (3)

<p>Because each vertical column ("Room") only has non-zero bits in a single row, summing the 8 shifted integers (<code>shifted.sum(dim=-1)</code>) is identical to a Bitwise OR (<code>|</code>). Every 4-bit weight drops cleanly into its own 4-bit slot without any carry or collision.</p>
<p>In hexadecimal (where 1 hex character represents 4 bits), you can read our 8 weights right-to-left inside <strong>Packed Word 0</strong>: <code>0x91C70FA3</code> (<code>3</code>, <code>A</code>=10, <code>F</code>=15, <code>0</code>, <code>7</code>, <code>C</code>=12, <code>1</code>, <code>9</code>). Doing the exact same shift-and-sum on <strong>Group 1</strong> (<code>[4, 14, 2, 8, 11, 5, 6, 13]</code>) produces <strong>Packed Word 1</strong>: <code>0xD65B82E4</code>.</p>
<blockquote>
<p><strong>Why do packed <code>int32</code> weights look negative in Python?</strong>
If you print <code>Packed Word 0</code> (<code>0x91C70FA3</code>) as a signed <code>int32</code>, Python displays <code>-1849225309</code>. Because Bit 31 (the leftmost bit of Room 7, where <code>9</code> = <code>1001</code> lives) is <code>1</code>, Two's Complement interprets the 32-bit word as negative. That does not corrupt a single bit—the GPU kernel ignores the decimal sign and reads the raw 4-bit fields directly.</p>
</blockquote>

<h3>How Unpacking Reverses the Process (<code>>></code> and <code>&#x26; 0xF</code>)</h3>
<p>When an inference kernel loads <code>Packed Word 0</code> (<code>0x91C70FA3</code>) from VRAM and wants to recover <code>codes[4]</code> (<code>7</code>, sitting in Room 4, bits <code>19..16</code>), it executes two single-cycle bitwise operations:</p>
<ol>
<li><strong>Right-Shift by 16 bits (<code>word >> 16</code>):</strong> Slides Room 4 all the way down into Room 0 (bits <code>3..0</code>), pushing Rooms 0–3 off the right edge:</li>
</ol>
<pre><code class="language-text">Room 7  Room 6  Room 5  Room 4  Room 3  Room 2  Room 1  Room 0
 0000    0000    0000    0000    1001    0001    1100   [0111]

</code></pre>
<ol start="2">
<li><strong>Bitwise AND with <code>15</code> (<code>&#x26; 0xF</code>):</strong> The mask <code>15</code> in binary is <code>0000...00001111</code>. Bitwise AND zeroes out Rooms 1–7 and isolates only Room 0:</li>
</ol>
<pre><code class="language-text">  0000    0000    0000    0000    1001    0001    1100   [0111]  (Word 0 >> 16)
&#x26; 0000    0000    0000    0000    0000    0000    0000    1111   (Mask = 0xF)
---------------------------------------------------------------
= 0000    0000    0000    0000    0000    0000    0000   [0111]  = 7!

</code></pre>
<p>Here is the standalone PyTorch verification compressing 16 <code>int32</code> weights (64 bytes) into 2 <code>int32</code> words (8 bytes) and unpacking them losslessly:</p>
<pre><code class="language-python">import torch

# 16 quantized 4-bit weights (0..15) stored in int32 (64 bytes)
codes = torch.tensor(
    [3, 10, 15, 0, 7, 12, 1, 9,  4, 14, 2, 8, 11, 5, 6, 13],
    dtype=torch.int32
)

shifts = torch.arange(8, dtype=torch.int64) * 4  # [0, 4, 8, 12, 16, 20, 24, 28]

# 1. PACK: [16] -> [2, 8] -> bit-shift into 8 rooms -> sum into [2] int32 words (8 bytes)
packed_words = (codes.to(torch.int64).reshape(2, 8) &#x3C;&#x3C; shifts).sum(dim=-1).to(torch.int32)
# packed_words: tensor([-1849225309, -698645788], dtype=torch.int32) -> ['0x91c70fa3', '0xd65b82e4']

# 2. UNPACK: [2] -> right-shift all 8 rooms -> mask with 0xF (15) -> flatten to [16]
unsigned = packed_words.to(torch.int64) &#x26; 0xFFFFFFFF
unpacked = ((unsigned.unsqueeze(-1) >> shifts) &#x26; 0xF).reshape(-1).to(torch.int32)

assert torch.equal(codes, unpacked)  # Exact match: [3, 10, 15, 0, 7, 12, 1, 9, 4, 14, 2, 8, 11, 5, 6, 13]

</code></pre>

<p>Here is the complete, end-to-end PyTorch implementation combining the Cholesky-stabilized GPTQ loop, dynamic group-wise <code>scales</code> and <code>zeros</code>, checkpoint bit-packing into <code>qweight</code> and <code>qzeros</code>, and the matching dequantization pass:</p>
<pre><code class="language-python">import torch

def get_group_qparams(w_group, bits=4):
    """
    Computes asymmetric scale (s) and integer zero-point (z) per output row.
    w_group shape: [N, group_size]
    """
    max_code = (1 &#x3C;&#x3C; bits) - 1  # 15 for 4-bit
    a = torch.minimum(w_group.min(dim=1, keepdim=True).values, torch.tensor(0.0, device=w_group.device))
    b = torch.maximum(w_group.max(dim=1, keepdim=True).values, torch.tensor(0.0, device=w_group.device))

    s = (b - a) / max_code
    s = torch.where(s == 0, torch.ones_like(s), s)
    z = torch.clamp(torch.round(-a / s), 0, max_code).to(torch.int32)
    return s.squeeze(1), z.squeeze(1)


def gptq_quantize_and_pack(W, H, bits=4, group_size=128):
    """
    Input:
      W: FP16/BF16 weight matrix of shape [N, K] ([out_features, in_features])
      H: FP32 Hessian matrix of shape [K, K] ([in_features, in_features])
    Output (Standard GPTQ Checkpoint Format):
      qweight: [K // 8, N]       int32   (8 input weights packed along K)
      qzeros:  [K // G, N // 8]  int32   (8 output zero-points packed along N)
      scales:  [K // G, N]       fp16    (1 scale per group and output neuron)
    """
    W = W.clone().float()
    N, K = W.shape
    pack = 32 // bits  # 8 values per int32
    num_groups = K // group_size
    max_code = (1 &#x3C;&#x3C; bits) - 1

    codes = torch.zeros((N, K), dtype=torch.int32, device=W.device)
    scales = torch.zeros((num_groups, N), dtype=torch.float16, device=W.device)
    zeros = torch.zeros((num_groups, N), dtype=torch.int32, device=W.device)

    # 1. Hessian Dampening &#x26; Upper Cholesky Inverse
    dead = torch.diag(H) == 0
    H[dead, dead] = 1.0
    W[:, dead] = 0.0
    dampening = 0.01 * torch.mean(torch.diag(H))
    H = H + torch.eye(K, device=H.device) * dampening

    L = torch.linalg.cholesky(H)
    H_inv = torch.cholesky_inverse(L)
    H_inv_chol = torch.linalg.cholesky(H_inv, upper=True)

    # 2. Vectorized GPTQ Loop (Marching left to right across K)
    for q in range(K):
        if q % group_size == 0:
            g = q // group_size
            s, z = get_group_qparams(W[:, q : q + group_size], bits=bits)
            scales[g, :] = s.to(torch.float16)
            zeros[g, :] = z

        w_q = W[:, q]

        # Encode to 4-bit integer code [0..15] and reconstruct float w_hat
        code_q = torch.clamp(torch.round(w_q / s) + z, 0, max_code).to(torch.int32)
        w_hat = s * (code_q.float() - z.float())

        codes[:, q] = code_q

        # Calculate error using reconstructed float and scale by Cholesky diagonal
        delta_q = w_hat - w_q
        scale_factor = delta_q / H_inv_chol[q, q]

        # Compensate remaining unquantized columns
        if q + 1 &#x3C; K:
            W[:, q + 1 :] += torch.outer(scale_factor, H_inv_chol[q, q + 1 :])

    # 3. Bit-Pack into GPTQ Checkpoint Layout
    shifts = torch.arange(pack, device=W.device, dtype=torch.int64) * bits

    # Transpose codes from [N, K] -> [K, N], then pack 8 rows along K into [K // 8, N]
    codes_kn = codes.t().contiguous().to(torch.int64)
    qweight = (codes_kn.reshape(K // pack, pack, N) &#x3C;&#x3C; shifts[None, :, None]).sum(dim=1).to(torch.int32)

    # Pack 8 zero-points along N from [groups, N] into [groups, N // 8]
    qzeros = (zeros.to(torch.int64).reshape(num_groups, N // pack, pack) &#x3C;&#x3C; shifts[None, None, :]).sum(dim=-1).to(torch.int32)

    return qweight, qzeros, scales


def unpack_and_dequantize_gptq(qweight, qzeros, scales, group_size=128):
    """
    Unpacks checkpoint tensors and reconstructs the [K, N] floating-point weight matrix.
    """
    shifts = torch.arange(0, 32, 4, device=qweight.device, dtype=torch.int32)

    # 1. Unpack qweight: [K // 8, N] -> [K // 8, 8, N] -> [K, N]
    w_int4 = ((qweight[:, None, :] >> shifts[None, :, None]) &#x26; 0xF).reshape(-1, qweight.shape[1])

    # 2. Unpack qzeros: [groups, N // 8] -> [groups, N // 8, 8] -> [groups, N]
    z_int4 = ((qzeros[:, :, None] >> shifts[None, None, :]) &#x26; 0xF).reshape(qzeros.shape[0], -1)

    # 3. Expand group parameters across group_size=128 and dequantize: w_hat = s * (c - z)
    s_expanded = scales.repeat_interleave(group_size, dim=0)
    z_expanded = z_int4.repeat_interleave(group_size, dim=0).to(scales.dtype)

    return s_expanded * (w_int4.to(scales.dtype) - z_expanded)
