Machine Learning Engineer

LLM inference · Agentic AI · Model evaluation

I'm a machine learning engineer working on LLM evaluation and inference. I like building systems, understanding where they break, and using measurements to guide what I improve next.

At Adobe, I built a multimodal LLM-as-judge framework to evaluate roughly 750 charts across ten quality dimensions and check model quality before releases. Working with domain reviewers and tuning the judge with DSPy improved its agreement with expert labels from 0.79 to 0.92 F1. That work taught me how much good evaluation depends on people agreeing on what a good answer looks like. Before that, at S&P Global, I worked on extracting information from financial documents using a LoRA-fine-tuned Llama 2 and OpenSearch hybrid retrieval, with an evaluation involving 100 analysts.

In my own projects, I've also explored recommendation and speech recognition. With IntentShop, I built a system that uses a shopping session to retrieve and rank the next products someone might want, then evaluated it on later sessions. With DeepSpeech2, I implemented a speech-to-text model in PyTorch and evaluated its transcriptions on LibriSpeech audio.

More recently, I've been digging into how inference engines work. I'm building small-vLLM with paged KV caching, continuous batching, and CUDA Graphs, and I've written FlashAttention-1 CUDA kernels that I check against PyTorch's attention implementation. I also write articles to work through the math behind methods like GPTQ and AWQ. Along the way, I've contributed two merged PRs to FastVideo and have an open PR to vLLM. I'd like to keep working at this intersection of implementation, evaluation, and performance.

I'm currently looking for machine learning engineer and data scientist roles.

Open source

  • FastVideo: OpenAI-compatible image endpoint and input validation (merged, PR #1840, PR #1841).
    FastVideo's image server did not answer at the address the standard OpenAI client calls, and it accepted unsupported output formats only to fail later. I added the /v1/images/generations endpoint and made the server reject bad formats up front with a clear HTTP 400 error, with regression tests for both.
  • vLLM: Tie-aware speculative-decoding logprob test (open, PR #53647).
    A vLLM test for speculative decoding was always skipped in CI because it asked for more GPU memory than the CI machines had, and when it did run, ties between equally likely tokens could make it fail at random. I lowered its requirement from 32 to 16 GiB so it runs again, and made it compare tokens by identity so ties no longer cause false failures.
